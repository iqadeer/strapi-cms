2. DIFFERENCES / ADAPTATIONS vs Strapi 5.52.1
--------------------------------------------------------------------
- Schema JSON format is identical between 5.0.4 and 5.52.1. The schema
  files can be copied 1:1 with NO content changes:
  * PascalCase attribute names (Title, HeroBanner, Banner, FAQSection,
    PageContent, ...) must be preserved exactly — the storefront
    (src/types/strapi.ts) depends on this exact casing.
  * collectionName values preserved verbatim (e.g. "components_about_us_whyuses"
    with the reference typo) — do NOT "fix" them.
  * info/options/pluginOptions/draftAndPublish preserved verbatim.
- File layout note: the task text suggests
  src/components/<category>/<component>/schema.json, but the ACTUAL
  Strapi 5 (and reference) convention for components is a single flat
  file: src/components/<category>/<kebab-name>.json. We follow the
  real Strapi 5.52.1 convention (same as reference).
  Content-type layout src/api/<name>/content-types/<name>/schema.json
  matches the task text and Strapi 5.52.1.
- Controllers/services/routes: NOT created by us. Strapi 5 generates
  the standard factory stubs automatically (develop/server bootstrap);
  if the build/server ever requires them, we add only the stock 3-line
  factory stub files (identical to Strapi's own scaffolding) — never
  custom logic.
- blog.Categories relation: declared oneToMany -> api::blog-post-category
  exactly as in the reference; Strapi auto-creates the inverse
  manyToMany ("posts") on the category side. Copied verbatim.
- No new npm dependencies required. No changes to package.json,
  config/*, .env, database config, or .gitignore.

UNCERTAIN (resolved at build/dev time, low risk):
- Whether `strapi build` accepts schema-only API folders without
